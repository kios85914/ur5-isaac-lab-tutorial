UR5 シーン構成

シミュレーション環境は _setup_scene() メソッドで構成されます。 ロボット本体、末端位置を計測するセンサ（FrameTransformer）、地面、照明の4要素から成ります。

Python — ur5_reach_env.py 
def _setup_scene(self):
    # 1. UR5 ロボットを生成
    self._robot = Articulation(self.cfg.robot_cfg)

    # 2. 末端エフェクタ位置センサ
    self._ee_frame = FrameTransformer(self.cfg.ee_frame_cfg)

    # 3. 地面を追加
    spawn_ground_plane(prim_path="/World/ground",
                       cfg=GroundPlaneCfg())

    # 4. 照明を追加
    spawn_light(prim_path="/World/light",
                cfg=DomeLightCfg(intensity=2500.0))

    # 5. シーンに登録
    self.scene.articulations["robot"] = self._robot
    self.scene.sensors["ee_frame"] = self._ee_frame

    # 6. 並列環境のクローン生成
    self.scene.clone_environments(copy_from_source=False)

UR5 ロボット構成

UR5は6自由度の産業用ロボットアームです。各関節の役割と設定を確認しましょう。

関節構造

関節番号関節名軸可動範囲役割

J2 shoulder_lift_joint Y軸 ±360° 肩の前後傾き
J3 elbow_joint Y軸 ±360° 肘の屈伸
J4 wrist_1_joint Y軸 ±360° 手首第1軸

アクチュエータ設定

各関節はPDコントローラで駆動されます。stiffness（剛性）は目標角度への追従強さ、 damping（減衰）は振動を抑える役割を持ちます。

Python — ur5_cfg.py 
UR5_CFG = ArticulationCfg(
    spawn=UsdFileCfg(
        usd_path=f"{UR5_ASSETS_DIR}/ur5_moveit.usd",
        rigid_props=RigidBodyPropertiesCfg(
            disable_gravity=False,
        ),
        articulation_props=ArticulationRootPropertiesCfg(
            enabled_self_collisions=True,
        ),
    ),
    actuators={
        "arm": ImplicitActuatorCfg(
            joint_names_expr=[".*"],     # 全関節に適用
            stiffness=800.0,             # 位置追従ゲイン
            damping=40.0,               # 速度減衰ゲイン
        ),
    },
    init_state=ArticulationCfg.InitialStateCfg(
        joint_pos={
            "shoulder_pan_joint":   0.0,
            "shoulder_lift_joint": -1.5708,  # -90°
            "elbow_joint":          1.5708,  # +90°
            "wrist_1_joint":       -1.5708,  # -90°
            "wrist_2_joint":       -1.5708,  # -90°
            "wrist_3_joint":        0.0,
        },
    ),
)
ホームポジション（実際の値）： shoulder_pan: -0.568 rad (-32.5°)、 shoulder_lift: -0.658 rad (-37.7°)、 elbow: 1.602 rad (91.8°)、 wrist_1: -2.585 rad (-148.1°)、 wrist_2: -1.606 rad (-92.0°)、 wrist_3: -1.641 rad (-94.0°)。 stiffness=800, damping=40 は安定したPD制御に適した値です。

末端エフェクタ位置を理解する

ロボットの末端（ハンド）がワールド座標のどこにあるかを知るには、 Isaac Lab の FrameTransformer センサを使います。 このセンサは、指定したフレームの位置・姿勢をリアルタイムで計測します。 関節角度から末端位置を計算する処理（順運動学）はPhysXが自動的に行います。

J1 … J6 (rad)
順運動学
PhysX 自動計算
EE 位置
X, Y, Z (m)
Python — 末端位置と関節角度の取得 
# 末端エフェクタのワールド座標位置を取得
def get_ee_pos_world(self) -> torch.Tensor:
    # shape: (num_envs, 3)  [x, y, z]
    return self._ee_frame.data.target_pos_w[..., 0, :]

# 現在の全関節角度を取得
def get_joint_positions(self) -> torch.Tensor:
    # shape: (num_envs, 6)  各関節の角度 (rad)
    return self._robot.data.joint_pos

# 目標位置との距離を計算
ee_pos  = get_ee_pos_world()            # (N, 3)

逆運動学 (IK) 制御

末端の目標位置 (XYZ) から関節角度を自動計算し、直感的にロボットを制御します。

順運動学 (FK) は「関節角度 → 末端位置」の計算で、PhysX が自動的に行います。
逆運動学 (IK) はその逆で、「目標の末端位置 → 必要な関節角度」を求めます。

Differential IK アルゴリズム

本環境では Isaac Lab の DifferentialIKController を使用します。 これはヤコビ行列の擬似逆行列を用いて、末端の位置誤差を関節角度の変化量に変換します：

Math — Differential IK 
# Differential IK の基本式
# Δq = J† × Δx
# q_desired = q_current + Δq
#
# J†  = ヤコビ行列の擬似逆行列 (pseudo-inverse)
# Δx  = 末端の目標位置 - 現在位置 (position error)
# Δq  = 関節角度の変化量 (joint delta)

使い方

手動制御スクリプトで ee コマンドを使います：

Terminal — IK で末端位置を指定

> ee 0.5 0.0 1.2

内部実装

Python — compute_ik() の実装 
def compute_ik(self, target_pos_w: torch.Tensor) -> torch.Tensor:
    # 1. 現在の EE 位置・姿勢を取得
    ee_pos_w  = self.get_ee_pos_world()
    ee_quat_w = self.get_ee_quat_world()

    # 2. ワールド座標 → ロボットベース座標に変換
    ee_pos_b, ee_quat_b = subtract_frame_transforms(
        robot_pos_w, robot_quat_w, ee_pos_w, ee_quat_w)

    # 3. IK コントローラに目標を設定
    self._ik_controller.set_command(target_pos_b,
        ee_pos=ee_pos_b, ee_quat=ee_quat_b)

    # 4. PhysX からヤコビアンを取得しベース座標に変換
    jacobian = robot.root_physx_view.get_jacobians()
    rot_mat = matrix_from_quat(robot_quat_w)
    jacobian_b = torch.bmm(rot_mat.transpose(1, 2), jacobian[..., :3, :])

    # 5. IK を解いて目標関節角度を計算
    joint_pos_des = self._ik_controller.compute(
        ee_pos_b, ee_quat_b, jacobian_b, joint_pos)

    return joint_pos_des  # shape: (N, 6)
実験してみよう： 同じ末端位置に対して ee X Y Z と手動の関節角度入力の両方を試してみましょう。 IK は「正解」を一瞬で計算しますが、手動では試行錯誤が必要です。 この差がまさに RL が解決しようとする問題です。
注意： IK は一般的に解が複数存在します（同じ末端位置に異なる関節角度の組み合わせで到達可能）。 また、目標位置がロボットの到達範囲外の場合、IK は最も近い到達可能な姿勢を返します。
なぜ強化学習が必要なのか？

IKは既知の環境で正確に動作しますが、以下の状況では限界があります：

  • 障害物がある環境での経路計画
  • 外乱やモデル誤差への適応
  • 複雑な目標（姿勢制御、力制御など）
  • 未知の動力学への対応

RLはこれらの課題を試行錯誤から学習することで解決します。

Part 2 — Environment

環境インタフェース

DirectRLEnv を継承した UR5 環境の構造と、観測・行動・報酬の定義を理解しましょう。

DirectRLEnv の5つの主要メソッド

_setup_scene ロボット・センサ・環境オブジェクトを生成し、並列クローンを構築する。
_get_observations エージェントに渡す観測テンソルを組み立てる。関節角度・速度・目標位置の15次元ベクトル。
_get_rewards 末端距離・tanh ボーナス・行動ペナルティを合算してスカラー報酬を返す。
_get_dones エピソード終了条件（ゴール達成 / タイムアウト）をチェックしてブールマスクを返す。
_reset_idx 完了した環境を再初期化し、新しい目標位置をランダムサンプリングする。

観測空間 (15次元)

次元 内容 サイズ 説明
0–5 関節角度 6 6つの関節の現在角度 (rad)
6–11 関節速度 6 6つの関節の角速度 (rad/s)
12–14 目標位置 3 ベース座標系での目標 XYZ 位置 (m)

行動空間 (6次元)

エージェントが出力する行動は、各関節への デルタ角度（変化量）です。 現在の関節角度に行動を加算して目標角度を計算し、PDコントローラへ渡します。 値の範囲はスケールにより制限されており、1ステップで大きく動きすぎないように設計されています。

Python — 行動の適用 
def _apply_action(self):
    # エージェントの出力: delta 関節角度 (num_envs, 6)
    delta = self._actions * self.cfg.action_scale

    # 現在角度 + delta = 新しい目標角度
    target = self._robot.data.joint_pos + delta

    # PD コントローラへ目標角度を送信
    self._robot.set_joint_position_target(target)

報酬関数

報酬は3つの項目から構成されます。距離ペナルティで大域的な誘導を行い、 tanhボーナスで目標近傍の精密な到達を促し、行動ペナルティで動作を滑らかに保ちます。

Python — ur5_reach_env.py 報酬関数 
def _get_rewards(self) -> torch.Tensor:
    ee_pos  = self.get_ee_pos_world()
    dist    = torch.norm(ee_pos - self._target_pos_b, dim=-1)

    # 1. 線形距離ペナルティ（遠いほどマイナス）
    r_dist  = self.cfg.reward_distance_weight * (-dist)

    # 2. Tanh ボーナス（目標付近で大きな正の報酬）
    r_tanh  = self.cfg.reward_tanh_weight * (
        1.0 - torch.tanh(dist / self.cfg.reward_tanh_std)
    )

    # 3. 行動ペナルティ（小さな動きを促進）
    r_action = self.cfg.reward_action_penalty * (
        -torch.sum(self._actions ** 2, dim=-1)
    )

    return r_dist + r_tanh + r_action

PPO アルゴリズムとは

PPO（Proximal Policy Optimization）は方策勾配法の一種で、 ポリシーの更新量を「クリッピング」によって制限することで学習を安定させます。 エージェントはロールアウト（データ収集）と最適化（ネットワーク更新）を交互に繰り返し、 累積報酬を最大化するポリシーを徐々に獲得します。 GAE（Generalized Advantage Estimation）を用いてバイアスと分散のバランスを取りながら アドバンテージ関数を推定する点が特徴です。

ハイパーパラメータ

パラメータデフォルト値説明
learning_rate3e-4学習率 (↓安定 / ↑高速)
rollouts24更新前のステップ数/環境
learning_epochs8更新ごとのエポック数
discount_factor0.99割引率 γ
entropy_loss_scale0.005探索の度合い
timesteps150,000総学習ステップ数

学習のヒント

1 少ない並列数から始める — まず --num_envs 8 で動作確認し、GPUメモリに余裕があれば増やします。
2 報酬曲線を監視する — TensorBoard で logs/ ディレクトリを監視し、報酬が単調増加していることを確認します。
3 安定したら並列数を増やす — 学習が安定していることを確認したら --num_envs 64 に増やして収集効率を高めます。
GPU メモリに関する注意： GPU メモリが 8GB 未満の場合は --num_envs 8 から始めてください。OOMエラーが出た場合は環境数を半分に減らします。環境数が多いほど1イテレーションで収集できるデータが増え学習が速くなりますが、メモリ消費も比例して増加します。

Part 1 — Step 2

Inverse Kinematics (IK)

Automatically compute joint angles from a target end-effector position (XYZ).

Forward Kinematics (FK) vs Inverse Kinematics (IK)
FK: Forward Kinematics
Joint Angles
6 values
EE Position
X, Y, Z
IK: Inverse Kinematics
EE Target
X, Y, Z
Joint Angles
6 values

This environment uses Isaac Lab's DifferentialIKController, which computes joint deltas using the pseudo-inverse of the Jacobian matrix:

Math — Differential IK
# Differential IK formula
# Δq = J† × Δx
# q_desired = q_current + Δq
#
# J†  = Jacobian pseudo-inverse
# Δx  = target_pos - current_pos (position error)
# Δq  = joint angle delta

Usage

Terminal — IK Control
# Move EE to world position (0.5, 0.0, 1.2)
> ee 0.5 0.0 1.2
  → IK target: (0.500, 0.000, 1.200)

# Verify with info
> info
  End-effector position: [0.501, 0.002, 1.198]
  Distance to target: 0.0031 m
Try it: Compare ee X Y Z with manual joint input for the same target. IK computes the answer instantly, while manual input requires trial and error. This gap is exactly what RL aims to solve.
Coordinate System: The ee X Y Z command uses world coordinates. The robot base is at z=1.05m (table height), so z=1.05 is roughly the table surface. Example: ee 0.5 0.0 1.3 → about 25cm above the table.
Why Reinforcement Learning? IK works well in known environments, but has limitations:
- Path planning with obstacles
- Adapting to disturbances and model errors
- Complex objectives (orientation, force control)
- Handling unknown dynamics
RL solves these by learning from trial and error.

Action Application

Python — _apply_action()
def _apply_action(self):
    current_pos = self._robot.data.joint_pos[:, self._arm_joint_ids]
    self._dof_targets = current_pos + self._actions * self.cfg.action_scale
    self._dof_targets = torch.clamp(self._dof_targets, self._joint_lower, self._joint_upper)
    self._robot.set_joint_position_target(self._dof_targets, joint_ids=self._arm_joint_ids)

Reward Function

Python — Reward
# 1. Linear distance penalty (farther = more negative)
r_dist = weight_d * (-dist)

# 2. Tanh bonus (high reward near target)
r_tanh = weight_t * (1.0 - tanh(dist / std))

# 3. Action penalty (encourages smooth motion)
r_action = weight_a * sum(action**2)

reward = r_dist + r_tanh + r_action
Part 2 — Training

PPO Training

Train the robot with Proximal Policy Optimization.

PPO (Proximal Policy Optimization) is a policy gradient algorithm that updates the policy by limiting the size of each update step. This prevents catastrophic performance drops during training.

Terminal
# 64 parallel envs (recommended)
python scripts/train_ppo.py --task Isaac-UR5-Reach-v0 --num_envs 64

# Low GPU memory
python scripts/train_ppo.py --task Isaac-UR5-Reach-v0 --num_envs 16
